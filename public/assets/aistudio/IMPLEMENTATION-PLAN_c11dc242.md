# operator-xconsole — Implementation Plan: functional Lab test app

**Goal.** Turn the scaffold into a working Android app whose job is to **exercise a Cloudflare
replacement for `cbridge`** (the "operator gateway"). When this plan is done, an operator can enrol
the phone, read plan state, approve real operations with a biometric, and run a **Lab** that fires
a catalogue of valid *and deliberately invalid* requests at a test gateway and reports pass/fail
per scenario, with a JSON report.

**Not the goal.** Production hardening, release builds, Play distribution, the gateway itself.

IDs: `T<phase>-<task>`; the task's hundreds digit is its stage (task 204 = stage 2 of its phase).
Prefix with the plan number when this plan is registered. Phases start at 1.

Path shorthand used below:
`M/` = `app/src/main/kotlin/com/inscopelabs/buildengine/`
`T/` = `app/src/test/kotlin/com/inscopelabs/buildengine/`
`A/` = `app/src/androidTest/kotlin/com/inscopelabs/buildengine/`

## 0. Rules for the AI Studio agent (standing + this plan)

1. **One stage per run.** Do exactly the stage you are given. Touch only the files listed in its
   tasks. Every other file must stay byte-identical (the push is a whole-tree snapshot, so
   unrelated edits silently overwrite out-of-band changes).
2. **Protected paths — never edit:** `.github/workflows/*.yml`, `proguard-rules.pro`,
   `AndroidManifest.xml`, `app/build.gradle.kts`, `version.properties`, `build-logs/**`.
   This plan was checked against the tree: the manifest already has `INTERNET` and
   `USE_BIOMETRIC`, and `app/build.gradle.kts` already has ktor, okhttp, serialization,
   biometric, datastore, mockk, turbine and mockwebserver. **No protected-path change should be
   needed.** If you believe one is, stop and put the exact requested diff in your report.
3. No release-build verification steps, no arbitrary shell setup commands, no HEAD drift checks.
   Write code and tests; CI (prerequisite P1) runs `:app:testDebugUnitTest` and
   `:app:assembleDebug` only.
4. **Never add:** any GitHub token/PAT/OAuth credential, `Runtime.exec`/`ProcessBuilder`, a git
   dependency, a `verify` screen, `bootstrap`/`init`, durable audit storage, or session tokens
   persisted across launches. (README "Deliberately absent".) The Lab export in Stage 5.1 is
   in-memory plus an explicit share action, not durable storage.
5. **Do not invent endpoints, fields or error codes.** The only source of truth for the wire is
   `docs/gateway-contract.md` (Phase 1). If the contract is silent, stop and report.
6. Every replaced placeholder removes its `SCAFFOLD PLACEHOLDER` KDoc line and `TODO("SCAFFOLD…")`.
   A task is not done while its files still contain either.
7. Redaction: no log line, error message, UI string or report may contain an operator credential,
   a lab secret, a signature or a nonce. Everything goes through `util/Logger` and `util/Redactor`.
8. **Report** (mandatory): `agent-reports/<UTC-ISO-timestamp>-<slug>.md` listing tasks completed,
   files changed, tests added, anything skipped and why, and any "stop and ask" items.

## 1. Prerequisites (done by Claude/user, not the agent)

| # | Prerequisite | Why |
|---|---|---|
| P1 | CI workflow in `.github/workflows/` running `:app:testDebugUnitTest` and `:app:assembleDebug` | Protected path; there is currently no CI, so nothing proves the scaffold compiles |
| P2 | Conformance vectors for the codec and signers (`docs/fixtures/vectors/*.json`) generated by a script, not hand-written | HMAC/ECDSA values cannot be computed reliably by the agent; wrong vectors poison both sides |
| P3 | A **test gateway** deployed with `/health` reporting `"environment":"test"`, plus fixture branches on a test consumer repo (table in T1-104) | The Lab needs something to talk to |
| P4 | `libs.versions.toml` Compose BOM check: file says `2026.06.01`, README says `2026.09.00`. Pick one and align them | Silent doc/build drift |
| P5 | Answers to decisions D-T1…D-T5 below | Phase 2 and 4 depend on them |

### Decisions needed before Phase 2

| ID | Question | Recommendation |
|---|---|---|
| **D-T1** | `capability-format.md` signs with **HMAC-SHA256 using a secret**, but Model B has the device sign with a **Keystore EC key** the gateway verifies by public key. These are different algorithms. | Keep the 10-field message unchanged. The **algorithm is a property of the `kid` in the gateway registry**, not of the wire. Support both signers: `HmacCapabilitySigner` (lab only) and `DeviceKeyCapabilitySigner` (ECDSA P-256). |
| **D-T1b** | Android's ECDSA output is **DER**; Cloudflare Workers' WebCrypto verifies **raw r‖s (P1363)**. | Contract mandates raw 64-byte r‖s, base64url no padding. Converter is a tested unit (T2-303). |
| **D-T2** | `halt`, `resume`, `upload`, `reconcile`, `sync` are not task-scoped, yet the format requires `branch` to match `^task-…`. | Task-scoped ops keep `^task-`; engine-scoped ops use the configured engine branch name as `branch` and its current head as `head`. Contract states the rule per `op`. |
| **D-T3** | ADR 0003 wants mTLS with the same key as the capability signature, but a `setUserAuthenticationRequired(true)` key cannot do a TLS handshake without a prompt, and `workers.dev` has no client-cert support. | **Defer mTLS** for the test app. Bearer operator credential + capability only. Record as ADR 0006. |
| **D-T4** | Play Integrity needs a Play project and may not exist on the test device. | Lab/enrolment uses **Keystore key attestation chain only**. `DeviceAttestation.requestAttestation` stays behind an interface, unimplemented, listed as deferred. |
| **D-T5** | Lab can mint without a biometric. | Allowed only when `/health` says `environment:"test"`; Lab refuses to run otherwise (T5-303). |

# Phase 1 — Contract, decisions and vectors (docs and fixtures only, no Kotlin)

**Gate:** the gateway team and this app can be built from the documents alone.

### Stage 1.1 — Gateway contract
- **T1-101 Contract skeleton.** Create `docs/gateway-contract.md`: auth (operator bearer
  header name, capability header or body field — pick one and state it), JSON content type,
  versioning, idempotency, timestamps.
- **T1-102 Endpoints.** Document each operation with request/response JSON, success status and
  errors, replacing the placeholder paths in `GatewayEndpoints.kt` if they differ:
  `/health`, `/plans`, `/plans/{id}/status|validate|render-check`, `/tasks/next`,
  `/tasks/{id}/publish|reconcile|upload`, `/halt`, `/resume`, `/sync`, `/doctor`,
  `/enroll`, `/enroll/rotate`, `/branches/{name}/head`. Include the **cbridge mapping**:
  `publish→publish`, `upload→upload`, `reconcile→reconcile`, `halt/resume→halt/resume`,
  `status→status`, `sync/verify-main→sync`, `doctor→doctor`; `init`/`bootstrap` explicitly out.
- **T1-103 Error taxonomy.** One stable machine code per rejection, each with HTTP status:
  `UNKNOWN_KID, BAD_SIGNATURE, EXPIRED, TTL_TOO_LONG, NONCE_REPLAYED, UNKNOWN_OP, BAD_FIELD_COUNT,
  BAD_ENCODING, BRANCH_NOT_TASK, BRANCH_MISMATCH, HEAD_DRIFT, HALT_ACTIVE, GUARD_FAILED(+guard id),
  OPERATOR_AUTH, NOT_ENROLLED, ENVIRONMENT_MISMATCH`. Group them into the four distinct UI states
  required by `ErrorMapper`: *scope refused*, *replayed*, *head drifted*, *halt active*.
- **T1-104 Fixture branches.** Table of named branches on the test consumer repo and the code
  each must produce. Derive cases from the guards in `build-engine`'s
  `template/operator/cbridge` (`guard_task`) and `tests/test_cbridge.sh`: not `task-*`; no commits
  beyond upstream; merge commit present; touches `engine/`, `plans/` or `.github/`; commit message
  matches `DENY_TEXT`; secret pattern in diff; disallowed author email; clean branch (must pass).
  Naming: `task-fx-<case>`.

### Stage 1.2 — Decision records
- **T1-201** `docs/adr/0004-lab-mode.md` (what Lab may do, environment guard, no durable store).
- **T1-202** `docs/adr/0005-signature-encoding.md` (D-T1, D-T1b, D-T2).
- **T1-203** `docs/adr/0006-mtls-deferred.md` (D-T3, D-T4). Update README "Deliberately absent"
  wording only if an ADR requires it.

### Stage 1.3 — Vectors
- **T1-301** Consume P2: add `docs/fixtures/vectors/README.md` describing the file layout
  (valid messages, per-mutation expected messages, HMAC and ECDSA signatures). Do **not**
  author signature values yourself.

# Phase 2 — Foundation (everything here is JVM-unit-testable)

**Gate:** `testDebugUnitTest` passes; codec and signers reproduce the vectors byte-for-byte.

### Stage 2.1 — Core utilities
- **T2-101** `M/core/crypto/Base64Url.kt` (no padding, strict decode), `M/core/time/Clock.kt`
  (system + fixed fake), `M/core/result/AppResult.kt`. Tests in `T/core/…`.
- **T2-102** `M/util/Redactor.kt`, `M/util/Logger.kt`: replace, not filter, patterns for bearer
  tokens, `github_pat_…`/`ghp_…`, base64url strings ≥ 40 chars after `sig`/`nonce` keys, secrets.
  Make `T/util/RedactorTest.kt` real.
- **T2-103** `M/core/crypto/SecureRandomSource.kt`; `M/capability/NonceSource.kt` +
  `DeviceNonceSource` (16 hex bytes minimum, never repeats within a run; test with fake random).

### Stage 2.2 — Codec and model
- **T2-201** `capability/model/*`: add validation to `OperatorCapability` (kid regex, exp > 0,
  head 40 lowercase hex, branch rule per `op` per D-T2, nonce charset).
- **T2-202** `capability/codec/OperatorCapabilityCodec.kt`: `encode` (LF-joined, 10 fields, no
  trailing LF/CR) and **strict** `decode` (reject extra/missing fields, CR, trailing LF, wrong
  literal). Make `T/capability/codec/OperatorCapabilityCodecTest.kt` assert against P2 vectors.

### Stage 2.3 — Signers and minter
- **T2-301** `HmacCapabilitySigner`: HMAC-SHA256 → base64url. Secret supplied at runtime.
- **T2-302** `SignedCapability` (message + signature + wire serialisation), `CapabilityMinter.mint`
  with TTL = 300 s from the injected `Clock`.
- **T2-303** ECDSA P-256 helpers: DER→raw r‖s and back, length checks. Tests with known DER
  samples from the vectors.
- **T2-304** `capability/signing/DeviceKeyCapabilitySigner.kt` delegating to `KeystoreSigner`
  (real Keystore use lands in Phase 4; here use an injected `java.security.Signature` provider
  so it is JVM-testable).
- `T/capability/signing/CapabilitySignerTest.kt`, `T/capability/CapabilityMinterTest.kt` become real.

### Stage 2.4 — Transport
- **T2-401** `core/network/dto/*` as `@Serializable` types exactly matching T1-102. Unknown JSON
  fields ignored on responses; missing required fields = parse error.
- **T2-402** `GatewayEndpoints`: replace `const BASE_URL` with a runtime value supplied by
  settings (default stays `https://gateway.invalid`); path templates from the contract.
- **T2-403** `GatewayHttpClient` (ktor + OkHttp engine): timeouts, bearer header, no redirects,
  response size cap, never logs bodies containing capabilities. `MtlsConfig` stays an unused stub
  per ADR 0006.
- **T2-404** `ErrorMapper` → the four distinct UI states plus others from T1-103.
- **T2-405** `data/remote/GatewayRepository` implementing every call. Make
  `T/data/remote/GatewayRepositoryTest.kt` use `MockWebServer` and cover each success and each
  error code.

# Phase 4 — Enrolment, confirmation and write operations

**Gate:** one real branch publishes end to end on the test gateway under a biometric-approved,
single-use capability; the gateway rejects reuse.

### Stage 4.1 — Device key and enrolment
- **T4-101** `core/crypto/DeviceKeySpec`, `DeviceKeyManager` (EC P-256, `AndroidKeyStore`,
  `setUserAuthenticationRequired(true)`, invalidated on biometric enrolment, StrongBox where
  available, non-exportable), `StrongBoxSupport` (`KeyInfo.isInsideSecureHardware` reported
  honestly), `KeystoreSigner` (real signing, raw r‖s output).
- **T4-102** `core/security/DevicePosture`, `ui/components/SecurityPostureBadge`.
- **T4-103** `DeviceAttestation.keyAttestationChain` only (D-T4). `requestAttestation` remains
  a documented stub behind an interface; the enrolment flow must not call it.
- **T4-104** `DeviceEnrollmentStore`, `EnrollDeviceUseCase`, `RotateDeviceKeyUseCase`,
  `ReportDevicePostureUseCase`, `ui/enrollment/*`. Enrolment sends public key + attestation chain
  to `/enroll`, stores the returned `kid`. Never enrols without an attestation statement.

### Stage 4.2 — Confirmation and minting (the single path)
- **T4-201** `core/security/BiometricPolicy` (explicit authenticators) and `BiometricGate`
  (`BiometricPrompt` with `CryptoObject` bound to the signing key).
- **T4-202** `domain/usecase/common/VerifyBranchHeadUseCase` (calls `/branches/{name}/head`;
  drift → refuse and ask for re-review).
- **T4-203** `ConfirmAndMintCapabilityUseCase`: **the only place a capability is created.**
  Order: verify head → show summary → biometric → mint. Add a unit test that fails if any other
  class constructs a `CapabilityMinter` call (reflection or source grep in the test).

### Stage 4.3 — Publish
- **T4-301** `PublishTaskUseCase`, `ui/publish/PublishConfirmScreen` (operation, branch, 40-char
  head, TTL countdown, posture badge, guard summary from the gateway), `PublishViewModel`,
  `PublishProgressScreen`, `OperationResultBanner` (shows the gateway `auditRef`).
- **T4-302** Make `T/domain/usecase/PublishTaskUseCaseTest.kt` real: success, each of the four
  distinct refusals, biometric cancelled, TTL expiry while the prompt is open.

### Stage 4.4 — Remaining cbridge operations
Each as one use case, one screen section, one capability, per D-T2 scoping:
- **T4-401** `HaltUseCase` / `ResumeUseCase` (global, separately scoped; never reuses a publish scope).
- **T4-402** `ReconcileUseCase` (plan, submission id, branches → shows `MERGED:`/`CLOSED:` outcome).
- **T4-403** `UploadSubmissionUseCase`: pick a `.zip` with the system document picker (no storage
  permission), cap size, compute SHA-256 on device, send. Client-side pre-checks mirroring cbridge
  (one `SUBMISSION.json`, safe paths, id regex, plan id match) behind a flag the Lab can switch off.
- **T4-404** `SetTaskStatusUseCase`, `CreateWorkOrderUseCase`, `DecideFrameworkUseCase` + `ui/decision`
  (own confirmation and attribution). If the contract (T1-102) omits these, skip and report.
- **T4-405** `sync` / `doctor` read-style calls surfaced on the dashboard.

# Phase 5 — Lab (the reason this app exists)

**Gate:** "Run all" executes the full scenario catalogue against the test gateway and produces a
report; a deliberately broken gateway fails the right scenarios.

### Stage 5.1 — Scenario engine
- **T5-101** `lab/Scenario.kt` (id, title, group, mutation, expected HTTP status, expected error
  code, optional fixture branch), `lab/ScenarioResult.kt` (actual status/code, pass/fail, latency
  ms), `lab/ScenarioRunner.kt` (sequential, cancellable, no retries).
- **T5-102** `lab/LabReport.kt`: JSON report (app version, gateway URL host, gateway
  `environment`, timestamp, per-scenario results, totals). **No signatures, nonces or credentials.**
  In memory; exported only through an explicit share action (`ACTION_SEND` text, no new permission).

### Stage 5.2 — Mutations
Applied by `lab/Mutator.kt`, either **before signing** (valid signature over bad content) or
**after signing** (valid content, bad signature).

| Group | Scenario | Stage | Expected |
|---|---|---|---|
| Baseline | valid publish of `task-fx-clean` | — | accepted |
| Identity | unknown `kid` | pre | `UNKNOWN_KID` |
| Signature | flipped bit / truncated / wrong-key signature | post | `BAD_SIGNATURE` |
| Time | `exp` in the past; TTL over the gateway maximum | pre | `EXPIRED` / `TTL_TOO_LONG` |
| Replay | same capability sent twice | — | accepted, then `NONCE_REPLAYED` |
| Encoding | extra field; missing field; CRLF; trailing LF | pre (raw) | `BAD_FIELD_COUNT` / `BAD_ENCODING` |
| Op | unknown `op` string (sent raw) | pre (raw) | `UNKNOWN_OP` |
| Scope | `branch=main`; branch ≠ work-order branch; `plan`/`task` mismatch | pre | `BRANCH_MISMATCH` |
| Race | stale `head`; wrong-length `head` | pre | `HEAD_DRIFT` / `BAD_FIELD` |
| Halt | publish while halted, then resume | — | `HALT_ACTIVE` |
| Auth | missing/invalid operator credential | — | `OPERATOR_AUTH` |
| Guards (cbridge parity) | one scenario per `task-fx-*` fixture in T1-104 | — | the code listed there |

- **T5-201** Mutator with unit tests proving each mutation changes only what it claims
  (e.g. flipped-bit mutation leaves the message identical).
- **T5-202** Scenario catalogue file `lab/ScenarioCatalogue.kt` built from this table and T1-103/104.
  A unit test asserts every error code in the contract has at least one scenario.

### Stage 5.3 — Lab UI and safety
- **T5-301** `ui/lab/LabScreen` + `LabViewModel`: scenario list with live status, run one / run
  group / run all, expected vs actual side by side, totals, export button.
- **T5-302** Lab mints with `HmacCapabilitySigner` and **no biometric**, so every Lab screen carries
  a persistent banner "LAB — not an operator approval". Real operations never use the lab signer.
- **T5-303** *Environment guard:* before any scenario, call `/health`; if `environment`
  is not exactly `"test"`, disable Lab and explain why. Unit-tested with fake responses.
- **T5-304** Toggle in Settings to enable Lab; off by default; the toggle is not persisted.

### Stage 5.4 — Contract self-check
- **T5-401** `lab/ContractCheck.kt`: validates gateway responses against the DTO schemas and
  flags unknown error codes (so a gateway drifting from `docs/gateway-contract.md` is reported,
  not silently tolerated).

## Definition of done

1. Unit tests green in CI (P1) and the debug APK assembles.
2. A fresh install can: set the gateway URL → test connection → enrol → read plans → publish
   `task-fx-clean` under a biometric → see the audit reference.
3. Lab "Run all" produces a report where every scenario matches its expected code against the
   reference test gateway, and at least three scenarios fail when pointed at a gateway with one
   guard disabled.
4. `grep -r "SCAFFOLD" app/src/main` returns only the deferred items in `docs/DEFERRED.md`.
5. No GitHub credential, `Runtime.exec`, git dependency or persisted session token exists anywhere
   in the tree.
