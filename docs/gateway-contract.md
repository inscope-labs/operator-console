# Operator Gateway Specification and Wire Contract (`v1`)

This document defines the HTTP API surface of the Cloudflare Operator Gateway (`cbridge` replacement)
and the contract between the Operator Console Android application and the gateway.

> **Revision 1.1 (BD-1.7, ADR 0013):** adds the client-generated `idempotencyKey` on every write request, the
> operation lookup semantics of §3.19, the status mapping of §4.3 and error codes `IDEMPOTENCY_KEY_INVALID`,
> `IDEMPOTENCY_KEY_REUSED`, `OPERATION_NOT_FOUND`. Pending operator merge; Gateway A does not implement it yet.

The gateway is the **sole enforcement point** for all repository operations. The console is untrusted
for enforcement; it functions as a scoped approval and minting client.

---

## 1. Protocol Architecture & Conventions

### 1.1 Transport & Framing
- **Protocol**: HTTPS (TLS 1.3 mandatory).
- **Default Port**: 443.
- **Content-Type**: `application/json; charset=utf-8` for all requests and responses containing a payload.
- **Character Encoding**: UTF-8 strictly required everywhere.
- **Wire Payload Format**: Standard RFC 8259 JSON.

### 1.2 Authentication & Authorization Headers
Requests sent to the gateway require two distinct authorization components:
1. **Operator Bearer Credential**:
   - Transmitted via standard HTTP header:
     ```http
     Authorization: Bearer <operator_credential>
     ```
   - Scoped strictly to the gateway administrative surface. Holds zero repository credentials.
   - Checked first on all privileged endpoints. Missing or invalid credentials return `OPERATOR_AUTH` (HTTP 401).
2. **Operator Capability**:
   - For mutating/privileged operations (`publish`, `reconcile`, `upload`, `halt`, `resume`), the signed capability is passed directly in the JSON request body field `capability`:
     ```json
     {
       "capability": "ctxop-v1\nk2\n1761840000\norder-7731\natlas\n10008\nPUBLISH\ntask-10008-refactor-parser\n9f2c1b7e4a5d6038c1b2a9e7d4f6081c3b5a7e9d\n7f3c9b1e5d2a7046\nsig_base64url_raw_rs"
     }
     ```
   - For write operations, the capability body field is mandatory.

### 1.3 Timestamps & Clock
- Capability timestamps (`exp`) are **Unix seconds** (integer epoch seconds).
- Response JSON representations use integer epoch seconds for machine-readable fields (e.g. `timestamp`, `enrolledAt`) and ISO-8601 UTC strings (`YYYY-MM-DDTHH:MM:SSZ`) for human-readable audit timestamps.
- Gateway clock skew tolerance: maximum 10 seconds.
- Default Capability TTL: **300 seconds (5 minutes)**. Maximum allowed TTL: **300 seconds**. Any capability with `exp - now > 300` is rejected with `TTL_TOO_LONG`.

### 1.4 Idempotency & Replay Protection
- Capabilities are strictly single-use.
- The `nonce` (minimum 16 hex characters) is recorded in gateway fast-storage prior to executing the operation.
- Re-presenting the same capability or nonce returns `NONCE_REPLAYED` (HTTP 409).
- Read operations are idempotent.
- Write operations additionally carry an **idempotency key** (§1.6). Presenting a key that the gateway has already
  recorded with the same request fingerprint returns the recorded outcome; it is **never** a re-execution.

### 1.5 Versioning & Extensibility
- Protocol version: `v1`.
- Capability domain separator: `ctxop-v1`.
- The client must ignore unknown JSON fields on gateway responses.
- The gateway must reject extra or unexpected fields in capability messages (`BAD_FIELD_COUNT`).

---

### 1.6 Operation idempotency key (BD-1.7)
- **What it is:** a random lookup label, **distinct from the capability nonce**. It is not a credential and grants nothing; a
  valid single-use capability is still required for every write.
- **Origin:** generated by the console when the operator starts an operation (128 random bits from a secure random
  source, encoded as 32 lowercase hex characters: `^[0-9a-f]{32}$`). The console journals it before sending and reuses
  it for repeated taps on the same intent. The gateway never issues keys.
- **Transport:** JSON body field `idempotencyKey` on every write request (`publish`, `reconcile`, `upload`, `halt`,
  `resume`, `decide`, plan status transition, and any later write endpoint). It is **not** part of the signed
  capability, so the capability format and the conformance vectors are unchanged. A missing or malformed key is
  rejected with `IDEMPOTENCY_KEY_INVALID` (400) and nothing is executed.
- **Gateway duty (write-ahead):** after Bearer authentication and key-format validation, and before capability
  processing, the gateway records `(operator credential, idempotencyKey) -> request fingerprint, status = pending`.
  Every later outcome, including refusals and failures, updates that record with its terminal status, `auditRef` where
  one exists, and the error `code`.
- **Fingerprint:** SHA-256 over the operation and every request field except `capability` and `zipBase64`
  (the upload is represented by `zipSha256`).
- **Reuse:** same key and same fingerprint returns the recorded response (same HTTP status and body) without
  re-executing and without consuming a nonce. Same key and a different fingerprint returns `IDEMPOTENCY_KEY_REUSED`
  (409) and executes nothing.
- **Scope and retention:** a record is visible only to the operator credential that created it, in the environment that
  holds it. Records are kept for at least 7 days.
- **Client rule:** the console never resends automatically. A resend after an uncertain outcome is a new operation
  with a new key, a new capability and a fresh operator confirmation, after review.

## 2. cbridge Command Mapping

The gateway directly replaces the legacy CLI `cbridge` while eliminating repository credentials from local machines.

| `cbridge` Command | Gateway Endpoint | Scope | Capability Required | Notes |
|---|---|---|---|---|
| `publish` | `POST /tasks/{id}/publish` | Task branch (`^task-`) | Yes | Runs task guard G1–G15 |
| `upload` | `POST /tasks/{id}/upload` | Task branch (`^task-`) | Yes | Uploads submission archive |
| `reconcile` | `POST /tasks/{id}/reconcile` | Task branch (`^task-`) | Yes | Merges/reconciles completed task |
| `decide` | `POST /plans/{id}/decide` | Task/Plan scope | Yes | Decision execution per BD-1.3 |
| `status` | `GET /plans/{id}/status` | Read-only | No | Returns plan status |
| `status` (transition) | `POST /plans/{id}/status` | Plan scope | Yes (`set` / `set_in_progress` / `set_done`) | Guarded status mutation with compare-and-swap per BD-1.3/BD-1.4 |
| `order` | `POST /plans/{id}/order` | Task scope | Yes (`ORDER`) | Work order minting |
| `operations` | `GET /operations/{id}` | Read-only | No (Bearer auth) | Operation lookup keyed by idempotency key per BD-1.7 |
| `audit` | `GET /audit` / `GET /audit/{ref}` | Read-only | No (Bearer auth) | Audit journal inspection |
| `halt` | `POST /halt` | Engine branch (`engine`) | Yes (Engine scoped) | Global emergency stop |
| `resume` | `POST /resume` | Engine branch (`engine`) | Yes (Engine scoped) | Resumes engine processing |
| `sync` / `verify-main` | `POST /sync` | Read-only / sync | No (Bearer auth) | Fast-forwards tracking |
| `doctor` | `GET /doctor` | Read-only | No (Bearer auth) | Verifies config & rulesets |
| `revoke` | `POST /admin/revoke` | Admin | No (Bearer auth) | Device key revocation per BD-1.10 |
| `init` / `bootstrap` | *EXCLUDED* | None | N/A | **Explicitly Out of Scope**; console never provisions repos |

### 3.19 `GET /operations/{id}`
Operation lookup for journal recovery (BD-1.7). `{id}` is the console's `idempotencyKey` (§1.6), never the nonce.

- **Auth**: Operator Bearer. No capability. Read-only: it never executes, retries or completes an operation.
- **Success Response**: `200 OK`
```json
{
  "id": "3b1f0c7a9e5d4a28b6c1d0e9f8a7b6c5",
  "operation": "PUBLISH",
  "status": "completed",
  "branch": "task-10008-refactor-parser",
  "headSha": "9f2c1b7e4a5d6038c1b2a9e7d4f6081c3b5a7e9d",
  "auditRef": "audit-20261030-98234",
  "timestamp": 1761840000
}
```
- `status`: `pending` (recorded, not terminal), `completed`, `failed` (the gateway ended the operation without
  completing it), `refused` (a guard or policy refused it). For `failed` and `refused` the body also carries `code`, a
  code from §4.1.
- **Errors**: `404 OPERATION_NOT_FOUND` if the gateway has no record visible to this credential: the request did not
  arrive, was never processed, or is still in flight; `400 IDEMPOTENCY_KEY_INVALID` for a malformed `{id}`.

## 4. Error Taxonomy & Status Codes

When a request is rejected, the gateway responds with standard HTTP error status codes and a structured body:
```json
{
  "code": "<MACHINE_READABLE_CODE>",
  "message": "<HUMAN_READABLE_SUMMARY>",
  "request_id": "<UUID>"
}
```

### 4.1 Error Code Registry

| Error Code | HTTP Status | Rejection Stage | Description |
|---|---|---|---|
| `UNKNOWN_KID` | `401 Unauthorized` | Identity | Key selector `kid` is not recognized in device registry. |
| `BAD_SIGNATURE` | `401 Unauthorized` | Signature | ECDSA or HMAC signature verification failed against registered key. |
| `OPERATOR_AUTH` | `401 Unauthorized` | Auth | Missing or invalid `Authorization: Bearer` operator credential header. |
| `CREDENTIAL_NOT_ACCEPTED` | `400 Bad Request` | Auth | Operator credential format is invalid. |
| `DEVICE_NOT_ENROLLED` / `NOT_ENROLLED` | `401 Unauthorized` / `403 Forbidden` | Enrolment | Device key attestation rejected or device has been revoked. |
| `ENROLL_CHALLENGE_INVALID` | `400 Bad Request` | Enrolment | Enrolment challenge is unknown, expired, or already used. |
| `ENROLL_ATTESTATION_INVALID` | `400 Bad Request` | Enrolment | Attestation certificate chain invalid, challenge mismatch, key mismatch, or tier mismatch. |
| `AUTH_TIER_NOT_ALLOWED` | `403 Forbidden` | Policy | Enrolment auth tier not permitted by gateway policy in this environment. |
| `BRANCH_MISMATCH` | `403 Forbidden` | Scope | Capability target branch does not match work order or request endpoint branch. |
| `ENVIRONMENT_MISMATCH` | `403 Forbidden` | Safety | Lab or test invocation executed against a production-configured gateway. |
| `CAPABILITY_EXPIRED` / `EXPIRED` | `401 Unauthorized` / `400 Bad Request` | Time | Capability expiry timestamp `exp` is in the past. |
| `TTL_TOO_LONG` | `400 Bad Request` | Time | Capability TTL exceeds the gateway maximum of 300 seconds. |
| `UNKNOWN_OP` | `400 Bad Request` | Format | Capability `op` is not member of closed `OperationType` enumeration. |
| `BAD_FIELD_COUNT` | `400 Bad Request` | Format | Wire message does not contain exactly 10 LF-separated fields. |
| `BAD_ENCODING` | `400 Bad Request` | Format | Contains CR (`\r`), trailing LF, invalid characters, or bad base64url padding. |
| `BRANCH_NOT_TASK` / `BRANCH_INVALID` | `400 Bad Request` | Scope | Task operation branch does not match required regex `^task-[A-Za-z0-9._-]+$` or is `main`. |
| `BRANCH_MISSING` | `404 Not Found` | Existence | Target branch does not exist on remote repository (G4). |
| `IDEMPOTENCY_KEY_INVALID` | `400 Bad Request` | Format | `idempotencyKey` is missing from a write request, or the key (or lookup `{id}`) is not 32 lowercase hex characters. |
| `IDEMPOTENCY_KEY_REUSED` | `409 Conflict` | Replay | The key is already recorded with a different request fingerprint. Nothing is executed. |
| `OPERATION_NOT_FOUND` | `404 Not Found` | Lookup | No record for this key is visible to the calling credential (`GET /operations/{id}`). |
| `NONCE_REPLAYED` | `409 Conflict` | Replay | Nonce has already been presented within its validity window. |
| `HEAD_MOVED` / `HEAD_DRIFT` | `409 Conflict` | Concurrency | Expected head SHA in capability does not match actual remote branch HEAD (G13). |
| `HALT_ACTIVE` | `423 Locked` | State | Global engine halt marker is active; write operations are blocked (G14). |
| `REPO_NOT_PRIVATE` | `403 Forbidden` | Security | Target repository is not verified private (G1). |
| `ANCESTRY_FAIL` | `409 Conflict` | Git Guard | Task branch is not a direct descendant of upstream base (G5). |
| `DELTA_EMPTY` | `400 Bad Request` | Git Guard | Task branch diff contains zero commits or empty tree delta (G6). |
| `MERGE_COMMITS` | `400 Bad Request` | Git Guard | Task branch diff contains forbidden merge commits (G7). |
| `DENIED_PATH` | `403 Forbidden` | Git Guard | Diff touches protected paths `engine/`, `plans/`, `.github/` (G8). |
| `SECRET_IN_DIFF` | `403 Forbidden` | Git Guard | Diff contains detected token or private key patterns (G11). |
| `SUBMISSION_IMMUTABLE` | `409 Conflict` | Lifecycle | Submission artifact identifier already recorded and cannot be overwritten (G15). |
| `GUARD_FAILED` | `422 Unprocessable Entity` | Guard | Generic cbridge guard check failed. |
| `UNKNOWN_REPO` | `400 Bad Request` | Adapter | Repository not registered in gateway configuration. |
| `RULESET_REJECTED` | `403 Forbidden` | Adapter | Upstream GitHub repository ruleset rejected compare-and-swap push. |
| `RECONCILE_REQUIRED` | `409 Conflict` | Adapter | Task branch requires manual reconciliation before state transition. |
| `TOKEN_UNAVAILABLE` | `503 Service Unavailable`| Adapter | GitHub installation token temporarily unavailable. |
| `RATE_BUDGET_LOW` | `429 Too Many Requests` | Adapter | Upstream GitHub rate limit budget exhausted. |
| `NETWORK` | `502 Bad Gateway` | Network | Upstream platform or network communication failure. |
| `CONFIG_INVALID` | `503 Service Unavailable`| Config | Gateway configuration or secrets invalid or missing. |

### 4.2 Mapping to UI States in `ErrorMapper`

The console's `ErrorMapper` maps incoming errors into one of four primary UI states (plus general authentication, format, and guard errors):

```
                       ┌────────────────────────┐
                       │   Gateway Rejection    │
                       └───────────┬────────────┘
                                   │
         ┌─────────────────────────┼─────────────────────────┬─────────────────────────┐
         ▼                         ▼                         ▼                         ▼
┌──────────────────┐      ┌──────────────────┐      ┌──────────────────┐      ┌──────────────────┐
│  Scope Refused   │      │     Replayed     │      │   Head Drifted   │      │   Halt Active    │
└──────────────────┘      └──────────────────┘      └──────────────────┘      └──────────────────┘
· BRANCH_NOT_TASK         · NONCE_REPLAYED          · HEAD_DRIFT              · HALT_ACTIVE
· BRANCH_INVALID                                    · HEAD_MOVED
· BRANCH_MISMATCH
· UNKNOWN_OP
· NOT_ENROLLED
· DEVICE_NOT_ENROLLED
· AUTH_TIER_NOT_ALLOWED
```

1. **Scope Refused**: The operation was rejected because the scope of the capability was denied (branch mismatch, invalid operation type, or device not enrolled). The user must not re-mint without reviewing scope.
2. **Replayed**: The nonce was already used. A fresh capability must be generated with biometric confirmation.
3. **Head Drifted**: The branch has advanced remotely since the operator reviewed it (`HEAD_DRIFT` / `HEAD_MOVED`). The UI prompts the operator to inspect the new HEAD SHA before approving.
4. **Halt Active**: The system is halted (`HALT_ACTIVE`). Write actions are locked until an authorized operator issues a RESUME.

### 4.3 Operation lookup status to console outcome (BD-1.7)

The console journals every write before sending it. Recovery uses `GET /operations/{id}` only; it never resends.

| Lookup result | Console outcome | Notes |
|---|---|---|
| `completed` | `Succeeded` only after the live-head check (T3-302); otherwise `UncertainCompletion` | `headSha` and `auditRef` are recorded |
| `pending` | `UncertainCompletion` | Look up again later |
| `refused` with `code` in {`HEAD_DRIFT`, `HEAD_MOVED`, `NONCE_REPLAYED`, `SUBMISSION_IMMUTABLE`, `ANCESTRY_FAIL`, `RECONCILE_REQUIRED`, `IDEMPOTENCY_KEY_REUSED`} | `Conflict` | |
| `refused`, any other `code` | `Refused` | Includes `HALT_ACTIVE` |
| `failed` | `RecoveryRequired` | Operator reviews; any retry is a new operation (§1.6) |
| `404 OPERATION_NOT_FOUND` | `RecoveryRequired` | Not proof the request was not processed; never an automatic resend |
| Lookup itself times out or the network is down | Entry unchanged | Retried by the recovery worker |
| `Timeout` | Reserved for a **write send** that received no response | Always followed by a lookup |
