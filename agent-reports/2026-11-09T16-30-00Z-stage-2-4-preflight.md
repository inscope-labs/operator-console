## 1. Summary of Changes

Stage 2.4 completes Phase 2 transport and connectivity verification by implementing a dedicated Preflight screen with 8 independent checks, extending the failure vocabulary across the client and domain layers, and completely removing the Crashlytics reflection hook per BD-2.3.

### 1.1 Tasks Completed

- **`T2-401` (Preflight Screen & 8 Independent Probes)**:
  - Created domain models in `com.inscopelabs.buildengine.domain.model.preflight.PreflightCheck.kt`:
    - `PreflightCheckId` (8 probes: `CONFIGURED`, `REACHABLE`, `TLS_PINNING`, `AUTHENTICATION`, `CLOCK_SKEW`, `CONTRACT_VERSION`, `ENROLMENT_STATE`, `POSTURE_TIER`).
    - `CheckStatus` (`PENDING`, `RUNNING`, `PASS`, `WARN`, `FAIL`).
    - `PreflightCheckResult` and `PreflightReport`.
  - Created `RunPreflightUseCase.kt`:
    1. **Configured**: Base URL exists and passes schema/host validation (`isConfigured`).
    2. **Reachable**: Gateway `GET /health` probe succeeds and returns HTTP 200.
    3. **TLS & Pinning**: SPKI pin set exists, matches hostname, and validates lifetime against BD-2.1/BD-2.2 (180 days minimum).
    4. **Authentication**: Gateway-scoped operator credential is present in the active environment slot. Warns if missing in test mode; fails in staging/production.
    5. **Clock Skew**: Strictly compares device epoch seconds against gateway timestamp. Enforces the contract's **10-second** maximum tolerance (fails if skew > 10 s; warns if 5 s < skew $\le$ 10 s; passes if $\le 5$ s).
    6. **Contract Version Compatibility**: Validates that gateway `environment` matches the configured `expectedEnvironment` and reports v1 compatibility.
    7. **Enrolment State**: Checks `DeviceEnrollmentStore` for an active enrolled device key in the target environment slot.
    8. **Posture & Accepted Tier**: Gathers hardware security backing, StrongBox availability, Key Attestation, and accepted auth tier per BD-3.1.
  - Implemented `PreflightViewModel.kt` with state flow and asynchronous execution.
  - Implemented `PreflightScreen.kt` using Jetpack Compose and Material 3:
    - Overview summary card with overall status badge, progress indicator, and action buttons.
    - Expandable card per check displaying title, status chip, summary, technical detail, and execution latency.
    - Quick actions to navigate to Settings or Enrolment if configuration or keys are missing.
    - Explicit `testTag` attributes for UI testing (`preflight_screen`, `preflight_back_button`, `preflight_refresh_button`, `preflight_action_settings_button`, `preflight_action_enrolment_button`, and `preflight_check_item_<id>`).
  - Added navigation route `Routes.PREFLIGHT = "preflight"` in `Routes.kt` and wired into `AppNavHost.kt`.
  - Added entry points:
    - Preflight action button in `SettingsScreen.kt` (`settings_preflight_button`).
    - Top bar FactCheck icon button on `DashboardScreen.kt`.

- **`T2-402` (Extended Failure Vocabulary)**:
  - Extended `GatewayFailureState` in `ErrorMapper.kt` with Guide §4.3 item 11 failure states:
    - `TLS_PINNING("tls_pinning")`
    - `AUTH("auth")`
    - `STALE("stale")`
    - `POLICY_REFUSED("policy_refused")`
  - Added mapping helpers in `ErrorMapper.kt`: `mapTlsPinning()`, `mapAuth()`, `mapStale()`, `mapPolicyRefused()`, and `mapException(Throwable)`.
  - Updated `GatewayRepository.health()` to catch `SSLPeerUnverifiedException` and route to `errorMapper.mapTlsPinning(...)`.

- **`T2-403` (Crashlytics Reflection & Diagnostic Hooks Removal per BD-2.3)**:
  - Deleted obsolete reflection classes:
    - `app/src/main/kotlin/com/inscopelabs/buildengine/diagnostics/FirebaseCrashReporter.kt`
    - `app/src/main/kotlin/com/inscopelabs/buildengine/diagnostics/CrashReporter.kt`
    - `app/src/main/kotlin/com/inscopelabs/buildengine/diagnostics/NoOpCrashReporter.kt`
    - `app/src/main/kotlin/com/inscopelabs/buildengine/diagnostics/CrashReporterManager.kt`
    - `app/src/test/kotlin/com/inscopelabs/buildengine/diagnostics/CrashReporterManagerTest.kt`
  - Cleaned up `DiagnosticSettings.kt` and `DiagnosticPreferences.kt` to retain local redacted gateway activity logging only (`PREF_GATEWAY_ACTIVITY_LOG`).
  - Removed reporter initialization from `BuildEngineApplication.kt` and `GlobalExceptionHandler.kt`.
  - Local redacted diagnostics (`CrashActivity`, `crash_logs.txt`, and memory activity log) are fully preserved.

- **Testing & Verification**:
